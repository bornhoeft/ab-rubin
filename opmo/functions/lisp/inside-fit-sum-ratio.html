Code walkthrough

Inside fit-sum-ratio

Five functions that turn a contour into n durations with an exact total, a shortest and a longest value, all on a rhythmic grid. Every step of the calculation, in plain terms, traced with real numbers.

All traces were run in SBCL 2.2.9. The Opusmodus functions half-sine, gen-transition and vector-map are not available there, so the worked examples use explicit contours, and fit-sum-om was tested with stand-ins (marked where it matters).

Overview

The idea in one picture

The file answers one question: how do I get n rhythmic values that follow a shape, stay between a shortest and a longest value, sit on a grid, and add up to exactly a given length?

Contourany list of numbers, e.g. half-sine
→
Normaliselowest point 0, highest point 1
→
Bendmap to MIN…MAX, curvature tuned until the sum fits
→
Snapscale, round to the grid, repair the sum
→
Exact ratiose.g. (1/4 5/8 1 …)

Get close — normalise and bend. Done with floating-point numbers, so the sum is only approximately right. fit-sum and fit-sum-om differ only here.

Land exactly — snap. Done with whole numbers by fix-rounding, so the sum is exact. Both variants share this part.

Counting in grid units

The trick behind the exact sum: fix-rounding never adds up 3/8 and 5/8 directly. It counts in whole grid units. On an eighth grid (unit 1/8), 3/8 is 3 units and a total of 4 is 32 units. Whole numbers add without any rounding error; multiplying back by 1/8 at the very end gives exact ratios.

The same words come up in every function below:

n
how many values you want
total
what they must add up to (a ratio, e.g. 8)
min, max
shortest and longest allowed value
quantize
the list of divisions allowed, e.g. '(1 2 4 8)
unit
the finest grid step those divisions share, e.g. 1/8
steps
the total, counted in units (8 ÷ 1/8 = 64)
lo, hi
min and max, counted in units
rest
units still missing (positive) or too many (negative)
err
how much a value lost or gained by rounding

grid-unit

(grid-unit quantize) → ratio
Source · fit-sum-ratio.lisp, lines 19–22 
19(defun grid-unit (quantize)
20  "Smallest common time unit of a QUANTIZE list.
21'(1 2 4) => 1/4, '(1 2 4 8) => 1/8, '(1 2 3) => 1/6."
22  (/ 1 (reduce #'lcm quantize)))

Finds the finest grid on which every division in the quantize list fits.

  1. Least common multiple

    (reduce #'lcm quantize) finds the smallest whole number that every entry divides evenly. For '(1 2 4 8) that is 8. For '(1 2 3) it is 6, not 3: halves (3/6) and thirds (2/6) only meet on sixths.

  2. Invert it

    (/ 1 …) turns the count into a length: one grid unit.

Takes any list of positive numbers, stretches it to the total, puts every value on the grid and repairs the rounding so that the sum is exact.

Worked example

(fix-rounding '(1/4 1/8 1/4 3/4 1 3/8) 4
              :quantize '(1 2 4))

  1. Grid unit and the total in units

    The grid is 1/4, so the total of 4 becomes 16 units. From here on, the goal is simply “six whole numbers that add up to 16”.

  2. Shortest and longest value, in units

    lo is MIN in units, rounded up so no value can fall below MIN; it is never less than 1, so no value can become zero. hi is MAX in units, rounded down so no value can exceed MAX.

    Without MIN, lo is 1 unit. Without MAX, hi is the whole total. In the example neither is given: lo = 1, hi = 16.

  3. Stretch to the total and convert to units

    Each value is multiplied by total ÷ sum and divided by the unit. Read it as two moves:

    raw = x · total ÷ sum ÷ unit × total ÷ sum keeps the proportions and makes the list add up to 4 (the input sums to 11/4). ÷ unit expresses the result in grid units.

    The raw values add up to exactly 16, but they are not whole numbers: 16/11, 8/11, 16/11 … ≈ 1.455, 0.727, 1.455 …

  4. Round down, then keep inside lo…hi

    Every raw value is rounded down with floor, then pushed up to lo or down to hi if needed. Rounding down means the list usually ends up a few units short, never over (except where a value was lifted to lo). In the example, 0.727 becomes 0 and is lifted to 1.

  5. Can it work at all?

    Six values of at least 1 unit need at least 6 units; six values of at most 16 units can hold up to 96. The target has to lie between:

    n · lo ≤ steps ≤ n · hi here: 6 ≤ 16 ≤ 96, so the repair in step 6 is guaranteed to succeed.

    If the test fails, no amount of moving units around could help, so the function stops with a message.

  6. Hand out the missing units

    rest is what is still missing: 16 − 14 = 2 units. err is what each value lost by rounding (raw − ints): positive means it was rounded down, negative means it was lifted.

    If rest is positive, the values are sorted by err, largest first, and each receives one unit, skipping any value already at hi, until rest is 0. If rest is negative, the order is reversed (most over-rounded first) and each gives one unit back, skipping values at lo.

    One pass gives each value at most one unit. If units are still left over, a new pass starts with freshly computed errors. If a whole pass moves nothing, the function stops with an error.

    This is the largest remainder method (the same idea used to share out parliament seats), with MIN and MAX added as limits.

  7. Back to ratios

    Units × 1/4: (2 1 1 4 6 2) becomes (1/2 1/4 1/4 1 3/2 1/2). The sum is 16/4 = 4, exactly, because it was built from whole numbers.

Runs the “can it work at all?” test before any curve fitting starts, and explains a failure in ratios rather than in units.

  1. Same conversions as fix-rounding

    unit, lo, hi and steps are computed exactly as in steps 1–2 above. Here MIN and MAX must be numbers; fit-sum always passes its defaults 1/8 and 1.

  2. Test the range

    Again n · lo ≤ steps ≤ n · hi.

  3. Report in musical terms

    On failure, the smallest and largest reachable sums are converted back to ratios (n · lo · unit and n · hi · unit), so the message tells you what is possible.

fit-sum

(fit-sum n total &key min max quantize shape) → ratios

93;;; --------------------------------------------------------

95;;;
96;;; Normalise the contour to 0.0 ... 1.0, then
97;;;   value = min + (max - min) * s^gamma
98;;; s=0 always gives min, s=1 always max -- the extremes
99;;; do not depend on gamma. Gamma changes only the
100;;; curvature and with it the sum, and is tuned to the
101;;; target sum by bisection. fix-rounding then does the
102;;; last, exact step onto the grid.
103;;; --------------------------------------------------------

105(defun fit-sum (n total &key (min 1/8) (max 1)
106                             (quantize '(1 2 4 8)) shape)
107  "N ratios with sum TOTAL, smallest value MIN, largest
108value MAX, all lying on the QUANTIZE grid.
109SHAPE is any contour of length N;
110default: (half-sine n 1 :phase 180)."
111  (check-sum-range n total min max quantize)
112  (let* ((raw (or shape (half-sine n 1 :phase 180)))
113         (a (reduce #'min raw))
114         (b (reduce #'max raw))
115         (s (if (= a b)
116                (make-list n :initial-element 0.5d0)
117                (mapcar (lambda (x)
118                          (coerce (/ (- x a) (- b a))
119                                  'double-float))
120                        raw)))
121         (curve (lambda (g)
122                  (mapcar (lambda (x)
123                            (+ min (* (- max min)
124                                      (expt x g))))
125                          s)))
126         (gamma (let ((g1 1d-4) (g2 1d4))
127                  (dotimes (i 200 (sqrt (* g1 g2)))
128                    (let ((m (sqrt (* g1 g2))))
129                      (if (> (reduce #'+ (funcall curve m))
130                             total)
131                          (setf g1 m)
132                          (setf g2 m)))))))
133    (fix-rounding (funcall curve gamma) total
134                  :quantize quantize :min min :max max)))

Follows the contour: high points become long values, low points short ones. It finds how strongly the contour has to be bent for the sum to come out right, then lets fix-rounding land it on the grid.

Worked example

(fit-sum 8 4 :shape '(2 5 8 7 4 1 0 3))
;; defaults: :min 1/8 :max 1 :quantize '(1 2 4 8)

  1. Check the range

    check-sum-range first. Eighth grid, total 4 = 32 units, lo = 1, hi = 8: 8 ≤ 32 ≤ 64, so it can work.

  2. Take the contour

    Either your :shape, or (half-sine n 1 :phase 180) — the Opusmodus generator for a half sine wave of length n and amplitude 1, where :phase sets the point at which the wave starts. Only the shape of the contour matters; its actual numbers are thrown away in the next step.

  3. Normalise to 0…1

    Find the lowest point a (here 0) and the highest b (here 8), then rescale every point:

    s = (x − a) ÷ (b − a) (2 5 8 7 4 1 0 3) → (0.25 0.625 1 0.875 0.5 0.125 0 0.375)

    The lowest point is now always 0 and the highest always 1. The values are turned into double floats, because the next step raises them to fractional powers, which cannot be exact ratios anyway. A completely flat contour (a = b) would mean dividing by zero, so every point simply gets 0.5.

  4. Bend the contour between MIN and MAX

    value = min + (max − min) · sγ

    Where s = 0 the value is always MIN; where s = 1 it is always MAX, whatever γ is. γ (gamma) only bends what lies in between. With γ = 1 the mapping is a straight line. With γ > 1 the in-between values sag towards MIN (0.5² = 0.25); with γ < 1 they bulge towards MAX (0.50.5 ≈ 0.71).

    Because every in-between value gets smaller as γ grows, the sum gets smaller too — steadily, never jumping back. γ is a single dial that turns in one direction, and that is what makes the search in step 5 possible.

  5. Find γ by halving the search range

    The search starts with γ between 0.0001 and 10000. Each round tries the middle, measures the sum and keeps the half that must contain the answer:

    Sum too big → more bending needed → raise the lower limit (g1 := m). Otherwise → lower the upper limit (g2 := m).

    The “middle” is the geometric mean √(g1 · g2), not the ordinary average. γ works by multiplication: 0.5 and 2 bend equally strongly in opposite directions. The ordinary average of 0.0001 and 10000 would be 5000, a useless first guess; the geometric mean is 1, a straight line.

    The bent values go to fix-rounding with the same quantize, MIN and MAX. Because their sum is already ≈ 4, the stretch in step 3 of fix-rounding changes almost nothing; the real work is rounding and repair: the floors add up to 29 of 32 units, so the three largest errors (values 2, 4 and 6) each receive one unit.

Does the same job, but lets Opusmodus do the bending: a value table plus a lookup. Only the exponent has to be found.

  1. Check the range and take the contour

    Identical to steps 1–2 of fit-sum. The contour is not normalised by hand here; the lookup in the next step takes care of that.

  2. Build a value table and look the contour up in it

    gen-transition produces a list of resolution (1000) numbers running from MIN to MAX; its fourth argument, the exponent e, sets the curvature, as the file’s comment describes. vector-map then maps the contour onto that list: the lowest contour point picks the first entry (MIN), the highest picks the last (MAX), everything in between proportionally.

    That is the sγ curve of fit-sum, in lookup form. resolution only sets how fine the table is (999 steps between MIN and MAX); the rhythmic grid still comes from quantize.

  3. The sum as a function of the exponent

    total-at builds the values for a given e and adds them up. This is the quantity the search has to steer to total.

  4. Find out which way the dial turns

    The sums at a very small (0.01) and a very large (100) exponent are compared. down is T if a larger exponent gives a smaller sum. Asking the function instead of assuming means the code works however gen-transition interprets its exponent.

  5. Halve the search range

    The same geometric halving as in fit-sum, between 0.01 and 100, for 100 rounds. The decision is packed into one line: (eq (> sum total) down) asks “do both answers agree?”. When they agree, the exponent has to go up (a := m); otherwise down (b := m).

    downsum > total?eq givesactionbecause
    TyesTa := ma larger exponent lowers the sum
    TnoNILb := ma smaller exponent raises it
    NILyesNILb := ma smaller exponent lowers the sum
    NILnoTa := ma larger exponent raises it

  6. Snap to the grid

    Exactly as in fit-sum: the looked-up values go to fix-rounding.

Tested with stand-ins

With a stand-in gen-transition (MIN + (MAX − MIN) · (i/999)e) and a proportional vector-map, the example contour gave (1/4 5/8 1 7/8 1/2 1/4 1/8 3/8) — identical to fit-sum — and the same result again when the stand-in’s exponent was reversed, which confirms the direction test. With the real Opusmodus functions the two variants can differ slightly, because gen-transition’s curve need not be exactly sγ. The single-float search limits (0.01, 100.0) are less precise than fit-sum’s doubles, which fix-rounding makes irrelevant.

Review

Things worth knowing

The sum is exact in every case tested. These points concern edge cases and wording, not the core calculation.

MIN and MAX are limits, not promises

The docstring says “smallest value MIN, largest value MAX”. Every value stays inside those limits, but they do not always appear. The curve pins every lowest contour point to MIN and every highest one to MAX. With c0 lowest and c1 highest points, bending can only reach sums between

(n − c1) · min + c1 · max  and  c0 · min + (n − c0) · max

If the target lies outside, γ runs to the end of its search range and fix-rounding has to shorten the longest or lengthen the shortest values. Example: (fit-sum 20 19 :shape '(0 1 2 … 9 9 … 2 1 0)) gives first and last values of 1/2, not 1/8. In a test with 2000 random contours (13 levels, n from 8 to 64, total 8) the sum was exact every time; MAX was missing in 741 results and MIN in 38, and every one of those cases lay outside this range. Contours with many repeated top or bottom values are affected most. At the ends of the n range (8 or 64 for total 8) every value is forced to MAX or MIN and the contour disappears entirely.

A total that is not on the grid is rounded silently

steps is (round (/ total unit)). (fix-rounding '(1 2 3) 4.1 :quantize '(1 2 4)) returns values summing to 4, and a total of 7/8 on a quarter grid gives 1 (3.5 units round to the even 4). A guard after line 41 would make this visible:

(assert (= steps (/ total unit)) ()
        "Total ~a is not on the ~a grid."
        total unit)

Ties depend on the Lisp

Common Lisp’s sort does not promise to keep equal elements in their original order. SBCL happens to (value 1 beat value 3 in the fix-rounding trace), but another implementation may not. For identical results everywhere, use stable-sort on line 60:

(stable-sort (loop for k from 0 below n collect k)
             (if (plusp rest) #'> #'<)
             :key (lambda (k) (nth k err)))

The “units left over” error can never fire

Once the assert on line 52 has passed and rest is positive, the values sum to less than steps ≤ n · hi, so at least one of them is below hi and can take a unit; the mirror argument holds for negative rest. Every pass therefore moves something. The error on lines 74–77 is a harmless safety net.

The assert restart cannot fix the total

Both asserts name (total) as a place, so the debugger offers to enter a new total. But the test uses steps, which was computed before the assert and is not recomputed, so the new value is ignored and the assert fails again. Writing () instead of (total) avoids the misleading offer.

“Everything stays rational” — at the ends

The header comment holds for fix-rounding with ratio input, and for every final result. Inside fit-sum and fit-sum-om the curve is computed in floats; the exactness comes from counting whole units at the end.

Which note value is 1?

Line 186 reads (fit-sum 20 8) as “8 quarters (two 4/4 bars), 1/8 … 1, on an eighth grid”. In OMN lengths 1 is a whole note, so make-omn on line 217 will read the result as eight whole notes — eight 4/4 bars, with values from an eighth to a whole note. That matches “eighth grid” but not “two 4/4 bars”. If two bars were intended, the result needs scaling by 1/4 before it goes into the score.
