Inside spread-develop

A development in which the IDs are spread: nine voices open out from a unison, widen, and draw together again above a moving transposition. Every step of the original spread-develop-om, the new plain Common Lisp spread-develop, and the chain that turns the rows into voice IDs — positions in a pitch material of 33 piano notes taken from the harmonic series on G-1.

Traced in SBCL 2.2.9 with 11 events. The Opusmodus functions (gen-integer, envelope-samples, envelope-y, rnd-number, integer-transpose, matrix-transpose) were replaced by stand-ins that behave as the docstring describes. A check at the end of spread-develop.lisp confirms this in Opusmodus.

Overview

IDs, spread and transposition

Two envelopes run over the same events. The transposition envelope sets the lowest ID of each chord. The spread envelope sets how far apart neighbouring voices are. Voice k of an event therefore gets:

ID = t + round(k · f) k = 0 … 8, the voice counted from the bottom · t = transposition · f = spread factor at this event

From ID to pitch and partial

The IDs are positions in the pitch material of the piece: the 33 piano pitches that lie within 6 cents of the chromatic scale among partials 4 to 181 of the harmonic series on G-1 (12.249859 Hz). Without transposition, ID 0 is the lowest of them, g1 (partial 4); ID 2 is g2 (partial 8); ID 32 is the highest, cs7 (partial 181).

Each tile: ID, piano pitch, partial, deviation from the chromatic scale in cents.

The selection keeps only partials that fit the piano, so it is sparse at the bottom and dense at the top: IDs 0–2 span an octave (g1 d2 g2), IDs 28–32 only a major third (a6 … cs7). A spread of f therefore means every f-th pitch of the material, as the usage comment says — not a fixed interval and not a fixed number of partials.

23(defun spread-develop-om (len env &key (variance 0.0)
24                                       steps round seed)
25  "Development in which LEN IDs are spread: row by row, the
26IDs 0 ... LEN-1 are multiplied by a spread factor that
27follows an xy envelope.
28ENV '(x1 y1 x2 y2 ...): x = step index, y = spread factor.
29By default one row per integer x step; STEPS overrides that
30count, and the x values then act as mere proportions.
31VARIANCE: a number, or its own xy envelope -- it is
32resampled to the same count, so its x range does not matter.
33Ex.:
34 (spread-develop-om 5 '(0 0 5 2 12 3 15 1 20 0) :round t)
35 (spread-develop-om 5 '(0 0 1 2 2.4 3 3 1 4 0) :steps 40)"
36  (let* ((base  (gen-integer 0 (1- len)))
37         (n     (or steps (1+ (- (car (last env 2))
38                                 (first env)))))
39         (curve (envelope-y (envelope-samples env n)))
40         (vars  (if (listp variance)
41                    (envelope-y
42                     (envelope-samples variance n))
43                    (make-list n
44                               :initial-element variance)))
45         (noise (rnd-number n -1.0 1.0 :seed seed)))
46    (loop for f in curve
47          for v in vars
48          for r in noise
49          for d = (+ 1.0 (* v r))
50          for row = (mapcar (lambda (y) (* y f d)) base)
51          collect (if round (mapcar #'round row) row))))

Builds one row per event: the voice numbers 0 … len−1, multiplied by the spread factor the envelope has at that event, optionally jittered and rounded.

Worked example

(spread-develop-om 9 '(0 0 30 1 70 4 100 1)
                   :steps 11 :round t)

  1. The voice numbers

    gen-integer counts from 0 to len − 1: (0 1 2 3 4 5 6 7 8). Each number is a voice’s distance from the bottom voice, measured in spread units. They are the same for every row; only the factor changes.

  2. How many rows

    With :steps, that number: 11. Without it, last x − first x + 1, one row per whole x step. (car (last env 2)) takes the last two elements of the envelope and returns the first of them, the last x. For this envelope that would be 101 rows.

    With :steps the x values only act as proportions: the same shape, compressed onto 11 events.

  3. Sample the spread envelope

    envelope-samples places n points evenly from the first to the last x; envelope-y keeps only their y values. With 11 rows the points fall on x = 0, 10, 20 … 100. Between two envelope points the value lies on a straight line: at x = 50, halfway from (30, 1) to (70, 4), f = 1 + 3 · 20/40 = 2.5.

    f01/32/311.752.53.254321

  4. Variance for every row

    A single number is repeated n times. An envelope is resampled to n values just like the spread, so its own x range does not matter: '(0 0 1 0.5) and '(0 0 100 0.5) give the same variance curve.

  5. One random number per row

    rnd-number gives n numbers between −1.0 and 1.0. With :seed they are the same on every run.

  6. The jitter factor

    d = 1 + v · r with v = 0.25, d lies between 0.75 and 1.25 · with variance 0 (the default) d is always 1

    d multiplies the spread of the whole row. The chord breathes wider or narrower, but all its voices move together, so they never cross.

    Variance 0.25, seed 7. The random numbers here come from the plain version; rnd-number gives different ones for the same seed. Rows 4 and 5 end up identical although their spread factors differ.

  7. Build the row

    Each voice number is multiplied by f and d: row = (0, f·d, 2·f·d … 8·f·d). The bottom voice is always 0; it will carry the transposition later.

  8. Round to IDs

    With :round t every value becomes the nearest whole number. Common Lisp’s round sends exact halves to the even neighbour: 2.5 → 2, 7.5 → 8 (see notes).

69(defun env-y-at (env x)
70  "Y value of the xy envelope ENV '(x1 y1 x2 y2 ...) at X,
71linearly interpolated. Beyond either end the end value
72holds. Two points with the same x make a vertical jump."
73  (if (<= x (first env))
74      (second env)
75      (loop for (xa ya xb yb) on env by #'cddr
76            while xb
77            when (<= x xb)
78              do (return
79                   (if (= xa xb)
80                       yb
81                       (+ ya (/ (* (- yb ya) (- x xa))
82                                (- xb xa)))))
83            finally (return (car (last env))))))

85(defun env-samples-y (env n)
86  "N evenly spaced y values of the xy envelope ENV, from
87its first to its last x, both ends included."
88  (let ((x0 (first env))
89        (x1 (car (last env 2))))
90    (loop for i below n
91          collect (env-y-at
92                   env
93                   (if (= n 1)
94                       x0
95                       (+ x0 (/ (* i (- x1 x0))
96                                (1- n))))))))

98(defun noise-at (seed i)
99  "Number from -1.0 to 1.0 for row I, fully determined by
100the integer SEED. A 32-bit integer hash (murmur3
101finalizer): neighbouring rows and seeds give unrelated
102values."
103  (flet ((u32 (x) (logand x #xFFFFFFFF)))
104    (let ((h (u32 (+ (* seed #x9E3779B9) i))))
105      (setf h (u32 (* (logxor h (ash h -16))
106                      #x85EBCA6B))
107            h (u32 (* (logxor h (ash h -13))
108                      #xC2B2AE35))
109            h (logxor h (ash h -16)))
110      (- (* 2.0 (/ h #xFFFFFFFF)) 1.0))))

112(defun spread-develop (len env &key (variance 0.0)
113                                    steps round seed)
114  "Plain Common Lisp version of SPREAD-DEVELOP-OM.
115Development in which LEN IDs are spread: row by row, the
116IDs 0 ... LEN-1 are multiplied by a spread factor that
117follows an xy envelope.
118ENV '(x1 y1 x2 y2 ...): x = step index, y = spread factor.
119By default one row per integer x step; STEPS overrides that
120count, and the x values then act as mere proportions.
121VARIANCE: a number, or its own xy envelope -- resampled to
122the same count, so its x range does not matter.
123SEED: an integer for repeatable noise (a different
124sequence from Opusmodus RND-NUMBER).
125Ex.:
126 (spread-develop 5 '(0 0 5 2 12 3 15 1 20 0) :round t)
127 (spread-develop 5 '(0 0 1 2 2.4 3 3 1 4 0) :steps 40)"
128  (let* ((n     (or steps
129                    (1+ (floor (- (car (last env 2))
130                                  (first env))))))
131         (curve (env-samples-y env n))
132         (vars  (if (consp variance)
133                    (env-samples-y variance n)
134                    (make-list n
135                               :initial-element variance))))
136    (loop for i below n
137          for f in curve
138          for v in vars
139          for r = (if seed
140                      (noise-at seed i)
141                      (- (random 2.0) 1.0))
142          for d = (+ 1.0 (* v r))
143          collect (loop for y below len
144                        for x = (* y f d)
145                        collect (if round (round x) x)))))

  1. env-y-at: one value of an envelope

    (loop for (xa ya xb yb) on env by #'cddr …) walks along the envelope two numbers at a time and looks at one pair of neighbouring points per round. The first segment whose right end xb reaches x is the one that counts, and the value is read off the straight line between its points.

    y = ya + (yb − ya) · (x − xa) ÷ (xb − xa) x = 50 between (30, 1) and (70, 4): 1 + 3 · 20 ÷ 40 = 5/2

    Before the first x the first y holds, after the last x the last y. Two points with the same x (a vertical jump) return the right-hand y.

  2. env-samples-y: n evenly spaced values

    xi = xfirst + i · (xlast − xfirst) ÷ (n − 1) i = 0 … n − 1: the first sample sits on the first x, the last on the last x

    With n = 1 there is no spacing to compute; the single sample sits on the first x. With whole-number envelopes everything stays exact: f = 1/3, not 0.33333334.

  3. The row count

    As in the original, except that the x range is rounded down with floor. With '(0 0 2.5 1) the Opusmodus version computes 3.5 rows and stops with an error in make-list; the plain version makes 3 rows, at x = 0, 1.25 and 2.5.

  4. noise-at: repeatable random numbers

    Common Lisp has no portable way to seed random with a number, so the seeded case uses a small hash instead of a random generator:

    The seed is multiplied by #x9E3779B9 (2³² divided by the golden ratio) and the row number is added. Three rounds of shifting and multiplying then scramble all 32 bits — the “finalizer” of the MurmurHash3 algorithm. The result is scaled to −1.0 … 1.0.

    The same seed and row always give the same number, in any Lisp. Each row is computed on its own, so row 7 does not depend on how many rows come before it. Without a seed, Common Lisp’s own random is used.

    Tested: 100 000 values spread evenly over −1 … 1 (mean 0.0009), with no correlation between neighbouring rows or neighbouring seeds.

  5. Build the rows

    Two nested loops take the place of mapcar over base. The outer loop runs over the events and carries f, v and the random number side by side; the inner loop multiplies the voice numbers 0 … len − 1 by f · d and rounds if asked.

Compared with the original

With variance 0, spread-develop returned exactly the same rows as spread-develop-om (with stand-ins) for 11 and 23 steps and for both docstring examples. Unrounded values differed by at most 0.000004, from exact fractions versus floats. With a seed, the two variants give different random numbers.

Review

Things worth knowing

IDs are positions in the pitch material

An ID is not a partial number. It is a position in the 33 pitches of the material: without transposition ID 0 is g1 (partial 4), ID 2 is g2 (partial 8), ID 32 is cs7 (partial 181). Partial numbers only come in at the end, through multiplicators, for the Pd sequencer.

The bottom voice of every row is 0 before transposition, so the lowest ID of an event is the transposition itself. At event 7 the transposition envelope reaches its point (70, 0), and voice 1 lands on g1.

The highest ID must stay at 32

(nth j pitch-mat) and (nth j multiplicators) return NIL for any ID above 32, so the voice would get no pitch and the sequencer no partial. The envelopes of the piece reach exactly 32: in the 11-event trace at event 7 (0 + 8 × 4), and with the piece’s 100 events at events 67–69 (traced with the stand-in resampling). Raising the transposition or the spread around x = 70, or adding variance, runs past the end: with variance 0.25 and seed 7, event 7 reached ID 35.

Doublings below f = 1

With a spread factor between 0 and 1, some voices share an ID (event 1: 2 2 3 3 3 4 4 4 5), so several voices sit on the same pitch. Nine distinct IDs need f ≥ 1. At f = 0 all voices form the unison the usage comment describes.

Exact halves go to the even ID

Common Lisp’s round rounds 2.5 to 2 and 7.5 to 8. With f = 2.5 the row becomes (0 2 5 8 10 12 15 18 20), with steps 2 3 3 2 2 3 3 2. Rounding halves up gives (0 3 5 8 10 13 15 18 20), steps 3 2 3 2 3 2 3 2 — a regular alternation. For that, replace (round x) in spread-develop with:

(floor (+ x 1/2))

In Opusmodus the envelope values are floats and can land a hair above or below .5, so in exactly these cases the two variants may differ.

Variance above 1 turns the fan over

d = 1 + v · r reaches 0 when v · r = −1. With variance 1.5 a row can get a negative factor and therefore negative values; a test gave rows like (0 0 −1 −1 −1). After transposition these can fall below ID 0, and (nth -1 pitch-mat) stops with an error, because nth accepts no negative index. Keep variance below 1: 0.25 means the spread breathes by ±25 %.

Check the resampling once in Opusmodus

The plain version assumes that envelope-samples includes both the first and the last x and interpolates linearly, as the docstring implies. The check at the end of spread-develop.lisp returns (:ENVELOPE T :ROWS T) if that holds. If it returns NIL, env-samples-y needs adjusting to Opusmodus’s sampling.
